# Omni free-first loop — 2026-09-23

## Decisions

- Keep the Go-only omni-proxy core on Spectre; do not deploy the desktop app.
- Route eligible Minecraft implement/mechanical packets through the existing
  visible Flash Orca pin with `--tier free`, not a new worker target. Preserve
  `target=flash` for authoritative worker-state monitoring. Review and blocker
  packets remain paid.
- Make free profile and proxy readiness fail closed before the bridge claims
  work. A definite free-readiness refusal requeues the packet on its original
  paid assignee and releases its dispatch reservation.
- Use distinct durable 24-hour trackers for Kimi and free DeepSeek packets;
  the vendor has not published whether their ceilings are shared. Persist a
  model-specific 429 from Go attempt telemetry even when paid failover makes
  the client response 200.
- Include free OAuth 401/403 in the on-box Go fallback status set for packets.
  A broken free login must not fail paid-capable work; Kimi has no configured
  fallback and therefore still fails its free-only probe.
- Require a real, one-token Kimi inference response before selecting the
  standby above Plus. Seat transfer remains operator-confirmed in Orca.

## Evidence and failures

- Fedora: final `bash verify.sh` passed bridge 64 tests, Devcodex 77 tests,
  and Python 404 tests. `shellcheck` was skipped because it is not installed.
- Fedora Go gate: `OMNI_SKIP_APP=1 bash scripts/verify.sh` passed Go race tests,
  `smoke: 89 passed, 0 failed`, and browser `24 passed, 0 failed`. The desktop
  app was intentionally skipped.
- Spectre temporary static Go proxy and synthetic Cline upstream: 20 direct
  Kimi requests, 101 free DeepSeek 429s with 101 paid fallbacks (one through
  real DSH headless), DSH exit 0, proxy RSS 16,180 KiB. The first fake SSE
  lacked `finish_reason`; DSH returned `dsh: TRANSPORT: Stream ended without
  finish_reason`. A corrected SSE passed. No permanent service was started.
- Spectre fake-OAuth refresh check: 20 concurrent Kimi calls returned `OK`
  through the Go core, one refresh occurred, and the rotated tokens were
  written to the mode-600 fixture. The real account was not contacted.
- The first staged `bash verify.sh` on Spectre failed on a real tmux-format
  discrepancy: this tmux replaced a combined tab delimiter with `_`, so pane
  cwd was not parsed and a wrong-worktree dispatch was admitted in the test.
  Separate tmux queries plus a missing-cwd refusal fixed the safety issue.
- The same staged gate initially picked up Spectre's older installed Slack
  agent registry and emitted a login MOTD inside vendored Devcodex shell tests.
  With `SLACK_AGENTS_FILE` pointing to the staged repository registry and
  `SPECTRE_MOTD_DONE=1`, the final staged `bash verify.sh` on Spectre passed:
  bridge 64 tests, Devcodex 77 tests, Python 404 tests. `shellcheck` was skipped
  because it is not installed. The temporary test tree was removed.
- A multiline generated JSON config exposed a launcher validation mistake:
  it treated the whole config as a single-line secret. The launcher now checks
  the config file mode separately from the two single-line keys.
- The loop initially dropped a packet when the Flash pin was busy. It now
  requeues that packet and releases the unused dispatch reservation.
